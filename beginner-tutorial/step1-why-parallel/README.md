## 📖 배경 지식

### 순차 처리 (Sequential)
```
작업1 → 작업2 → 작업3 → 작업4
시간: ████████████████
```

하나씩 차례대로 처리합니다.

### 병렬 처리 (Parallel)
```
작업1 →
작업2 →
작업3 →
작업4 →
시간: ████
```

여러 작업을 동시에 처리합니다!

## 🚀 실험 2: 병렬처리로 개선

### 실행하기
```bash
python3 fast_program.py
```

**무엇이 다른가요?**
- 같은 작업을 병렬로 처리
- 여러 CPU 코어 동시 사용

**실행 결과:**
```

총 시간: 1.12초
속도 향상: 8.9배!
```

### 🎉 빠르죠!

10초 → 1초로 단축! 거의 9배 빠릅니다!

## 📝 정리: 언제 병렬처리를 사용할까?

### ✅ 병렬처리가 좋은 경우

1. **같은 작업을 여러 번** 반복
   - 예: 1000개 파일 처리
   - 예: 100만 개 데이터 계산

2. **각 작업이 독립적**
   - 작업1이 작업2에 영향 없음
   - 순서가 중요하지 않음

3. **각 작업이 충분히 무거움**
   - 최소 몇 밀리초 이상
   - 너무 가벼우면 오히려 느림

### ❌ 병렬처리가 나쁜 경우

1. **작업이 순차적**
   - 작업2가 작업1의 결과 필요
   - 예: 1+2+3+4... (순서대로)

2. **작업이 너무 가벼움**
   - 마이크로초 단위
   - 병렬화 오버헤드가 더 큼

3. **공유 자원에 접근**
   - 여러 작업이 같은 파일 수정
   - 데이터 경쟁 발생 가능

---

## 🧮 속도 계산하기

### 이론적 최대 속도

```
최대 속도 향상 ≈ CPU 코어 수
```

**예시:**
- 4코어 CPU → 최대 4배
- 8코어 CPU → 최대 8배

### 현실적 속도

```
실제 속도 ≈ 코어 수 × 0.7~0.9
```

**왜 덜 빠를까?**
- 오버헤드 (관리 비용)
- 데이터 복사 시간
- 코어 간 동기화

## 💡 더 알아보기 (선택)

### Amdahl의 법칙

병렬화할 수 없는 부분이 있으면 최대 속도가 제한됩니다.

```
최대 속도 = 1 / (순차 비율 + 병렬 비율 / 코어 수)
```

**예시:**
- 작업의 20%는 순차적
- 80%는 병렬 가능
- 무한대의 코어 → 최대 5배
